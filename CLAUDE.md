# Quaera — инструкции для агента

Тренажёр аналитика данных: SQL, pandas, модель данных и BI, метрики рынка —
на одном сквозном синтетическом датасете дистрибьютора. PWA, офлайн,
без сервера в рантайме. https://quaera.app

## Перед первой правкой — два клона на диске

**На диске может быть больше одного клона этого репозитория.** Перед тем как
редактировать что угодно, свериться с origin:

```bash
git fetch origin && git status
```

Если `git status` говорит «behind N commits» — сначала `git pull --ff-only`,
потом правки. Признак, по которому промах вскрывается только в браузере:
правки на диске есть, `tsc`/гейты зелёные, а dev-сервер показывает старый
текст — значит сервер поднят из другого каталога, чем тот, где правили.
Проверить одним вызовом: запросить у dev-сервера сам файл
(`fetch('/src/content/packs/sql-core.en.json?t='+Date.now())`) и сравнить
со строкой на диске.

## Домен и что это за проект

Автор — специалист по PMO в промышленном строительстве (планирование,
отчётность, cost control), **не FMCG/фарма**. Домен датасета (FMCG,
дистрибуция, sell-in/sell-out, TRx/NRx) выбран и осваивается по ходу
постройки тренажёра, а не принесён из опыта. Не путать одно с другим —
это меняет, какие доводы о проекте верны (например, «автор отвечает
на domain-вопросы из своего опыта» — неверно).

Цель проекта на 2026-08-22: **портфолио под найм в аналитику**, в этом же
порядке — живые прохождения → дописать позиционирование → сообщество.
Академический трек (Nova) возможен позже и этому не противоречит.

## Гейты — обязательны после любой правки контента, генератора или UI с данными

```bash
npm run verify
```

15 шагов (`verify:data`, `verify:content`, `test:scheduler`, `test:merge`,
`test:chart`, `test:schema-layout`, `test:prose-en`, `test:text-grade`,
`test:storage-migration`, `test:grade-compare`, `test:push-schedule`,
`test:css-width`, `test:story-line`, `test:story-ladder`,
`test:lesson-figure`). Каждый уже ловил реальный дефект в первый прогон —
не формальность.

**Гейты статические: DOM, раскладку, контраст, обрезание текста они не видят
вообще.** Такие правки проверяются замером в браузере и глазами.

**Новый приём трека добавлять в `scripts/lib/track-constructs.mjs`** — этот
список читают два гейта сразу: verify-content спрашивает «объяснён ли приём
в теории», гейт лестницы — «показан ли он в кампании прежде, чем человек
печатает его рукой». Пока список был приватным для verify-content, лексикон
лестницы отставал на целый трек и день на pandas проходил проверку вхолостую.

**Прогонять шаги по одному в foreground, не всей командой в фоне** — одной
командой `npm run verify` однажды зависал на 10+ минут без вывода.

После правки — ещё и типы:

```bash
npx tsc --noEmit
```

Отдельно, без гейтов: `npm run count:rows` — самопроверка объёма данных,
намеренно не гейт (падать не должна, только информирует).

## Английская локаль — тире

`src/i18n/en.ts` держит бюджет тире на **нуле**: новый английский текст
интерфейса пишется без тире сразу, не через правку после. Контент-паки
(`*.en.json`) считаются тем же гейтом (`test:prose-en`) с целью ≤2 на 1000
слов — там тире изредка допустимы, в `en.ts` нет.

## Как вести работу (согласовано с пользователем, не менять по умолчанию)

- **Структура и архитектура — в чате до кода.** Перед правкой, которая
  трогает больше одного файла или заводит новую сущность: короткий разбор
  в чате (что за структура, какие развилки, рекомендация и почему), ждать
  подтверждения и только потом код. Мелкие правки внутри уже согласованной
  структуры — без этого круга. Причина: цена ошибки здесь в токенах,
  не в правках.
- **Крупная работа — фазами**, каждая со своим коммитом и остановкой на
  проверку. Модель распределяется по фазам: Opus там, где решение задаёт
  правила для следующих фаз или трогает код с состоянием; Sonnet — где
  правила уже заданы и работа механическая.
- **После каждого захода — короткий план**: следующие 2–4 шага, у каждого
  модель и одна фраза причины.
- **Коммит и пуш в `origin/main` — авторизованы как постоянный паттерн**,
  не разовое разрешение. После каждого законченного шага (гейты зелёные,
  `tsc` чист, проверено в браузере) — без повторного переспроса. Сообщение
  коммита на русском, тело объясняет «почему», подпись
  `Co-Authored-By: Claude <модель> <noreply@anthropic.com>` с реальным
  именем модели захода. Один коммит — одна логическая правка.
- **Ревью по скриншоту — отдельный шаг, всегда после замеров.** Замеры
  (`getBoundingClientRect`, `scrollWidth` против `clientWidth`, контраст
  через `getComputedStyle`) ловят не всё: подтверждено семь раз подряд —
  задвоенные заголовки, слипшиеся соседи, обрезание многоточием, инверсия
  цвета видны только глазом. Проходить экран сверху вниз без остановок,
  повторять проход на второй локали (`?intro`-подобные страницы) — многое
  видно только при чтении подряд или при переключении языка.
- **Не делегировать фоновым агентам без явного запрета делегирования
  первой строкой промта.** Без него агент способен отчитаться «готово»,
  запустив под-агентов, которые не вернули результат вызывающей сессии.
- **`git add -A` после сессии со скриншотами — осторожно.** Черновой снимок
  из корня однажды уехал в коммит вместе с несвязанной правкой. Добавлять
  файлы явным списком.

## Dev-сервер

Поднимается из `.claude/launch.json` **каталога сессии** (на уровень выше
этого репозитория): `npm run dev --prefix querium`. Если правите в другом
клоне — сервер всё равно будет показывать этот, рабочий.
